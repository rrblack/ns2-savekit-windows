# Code review and test evidence

This is the offline review of the build that was later used on hardware (see the README). In the reviewed package, the six host changes were full replacement modules. This repository ships them as diffs in `patches/` instead, and the installer checks that each result matches the reviewed module byte for byte (`overlays.json`). "Overlay" below means those six changes. "Previous four-file overlay" refers to an earlier, superseded integration attempt that is not published.

Reviewed November 7, 2026. The working engine and run.cjs that were examined exactly match the BermTheSequel main checkout at the pinned revision. The examined inputs also included an older patched engine, eight patch files from an earlier attempt, both runners and the previous four-file overlay. The savekit tools came from their pinned upstream revision.

## What changed in the working host

| Path under engine | Finding and change |
| --- | --- |
| shared/ipc.cjs | The overlay placed dataWords before A/B map descriptors and placed the variable receive-pointer size table immediately after odd-length input. Mixed descriptors could overwrite other data and point the receiver to the wrong offsets. The correction starts data words after all descriptors and halfword-aligns the size table. The usual ListAllUsers call only uses a receive pointer and zero input. The mixed-descriptor bug alone does not explain the older missing-tmp failure. |
| switch2/app/mounted-save.cjs | Export the existing validated inspector, plus the addresses used by savekit's optional find-save-uid tool. Preserve the newer save-only fallback, SDK instruction checks, object/manager validation and borrowed-handle ownership. This helper inspects the host application's existing mount. Other games are opened using a separate read-only FS command. |
| switch2/ro/ncm.cjs | Preserve the original query defaults and validate returned metadata types against the actual request. The overlay removed that validation and overwrote earlier diagnostic files. Permit the additional application/storage selectors used by list-apps, keep exclusive capture creation and use unique per-query filenames. NCM naming is optional for whole-store exports. |
| lib/bridge.cjs | Include failure details only when the native connection has failed. Always emitting an extra error:null property broke the upstream runner's exact healthy-status test. |
| switch2/cleanup-scratch.cjs | The baseline deletes every pre-existing root entry whose name starts with NS2_GAP. On SmileBASIC's save mount, refuse existing prefix matches. When the donor uses that same save, refuse pre-existing main and main.npdm before acquisition. The original cleanup paths for session-owned scratch and tmp remain in place. A leftover from a failed run can therefore stop this copy for inspection. |
| switch2/ro/files.cjs | Also refuse stale donor removal at point of use when its backing mount is the application save. Original donor creation, hash checks, owned-file removal, commits and retirement remain intact. |

The older cleanup alone did not fix the second failure. In the older tree, probe-reserved-gap calls cloneMountedFilesystem for tmp and the inspector requires that mount. In the working tree, cleanup enumerates captured mounts, the probe allocates two handles backed by save when tmp is missing, accounts for combined free space, and creates the scratch tree once. Donor preparation picks the actual mount. No substitution was made in probe-reserved-gap, fs-memory-control, run-control, acquisition, retained-memory selection, the native payload, the pipeline, or run.cjs.

The older session diagnostic patch improves an error string. The additional pin-window, metadata-attempt and pairing-timeout patches change launch policy and are unnecessary for the savekit protocol. The export client reads bridge status directly. No acquisition checks, firmware checks, timing bounds or active-run retirement safeguards were weakened.

The host keeps a loopback HTTP application bridge and a retained endpoint identified by current-acquisition.json (a named pipe on native Windows). Both are needed. The backup client checks hashes of the current run copy, the held/restored execution proof, matching session IDs, the pid-1 root proof, bridge readiness and the retained native worker's idle state. It borrows the promoted root without adding it to the client’s owned handles. Ordinary import of an engine module outside a prepared run may require connection.json or captured mount state. Syntax alone does not exercise that dependency.

## Store enumeration, identity and verification

The previous overlay does not fix tool-side behavior. The pinned upstream bulk client drops zero UIDs from its argument list, only passes rank/index for cache records, restricts --all-types to types 1–5, filters out zero application IDs, and normally selects only space 1. Its manual puller plans alternate UIDs even for a requested account. In the integration fixture a locked account and a valid common save shared the same application ID. Stock pull-inventory reported the locked account as done and wrote a manifest identifying the all-zero common UID. The corrected exporter made exactly one cmd 53 attempt with the inventory attributes and reported the locked account as refused.

Stock save-inventory reads rank from 0x0a and a 32-bit index from 0x0c, inside padding. The documented 0x60 record instead stores the static ID at 0x20, application ID at 0x28, little-endian index at 0x38 (u16) and rank at 0x3a (u8). The corrected reader retains all 96 raw bytes, follows short pages through the explicit end-of-list, records service errors, and refuses to treat capped or malformed data as complete. An ambiguous attribute tuple remains unsupported because cmd 53 opens by attributes and takes no dynamic save ID. Zero application/system identifiers with no selector are reported rather than guessed.

The pinned savekit packer and tree walker are included with their MIT license. The exact exporter uses the same checked Session, domain, filesystem.openFile, filesystem.listDirectory, filesystem.fileSize and filesystem.readFile paths through the copied runtime. It always uses read-only archive open 53, directory mode 3 (list both entry types), and file mode 1 (read). It never calls savekit's write, restore, delete, launcher, --keep-open or the system-specific open command 52. Its writes to guest memory fill the client's own IPC buffers. Its filesystem outputs go to the PC. The host's earlier scratch files and donor transactions are separate and are real console writes.

The stock puller creates output files with 'w', writes manifest.json inside the same tree as game files, and infers bulk success from exit status and a text line. Its standalone verifier can accept zero entries or partial manifests without establishing a complete archive. The new exporter stages each archive in a unique folder, keeps metadata separate from the game's namespace, checks short reads/writes and file sizes, preserves empty directories, uses the engine's console-computed chunk hashes, then reopens and rehashes PC files before promotion. Coverage is computed against the inventory, including refused, failed and unknown spaces. A manifest is an integrity record, not a signed attestation from the game.

Stock read-only scripts can still be pointed at the fresh run folder. Their reviewed caveats still apply. Optional kit functions call /bin/sh or Python and include write-capable actions. The provided workflow uses its own pinned backup client. An accessible logical filesystem export cannot promise a raw save-container image, an external save meta file, or a successful restore.

## Evidence

- Source comparison covered both complete uploaded engine trees, run files, all eight patch descriptions and diffs, and the four overlay replacements. Both ZIPs passed CRC checks. The installer verifies SHA-256 for the complete runtime baseline before creating the installed copy.
- On Linux with Node 24.22.1, all 18 upstream host tests and all 10 retained/layout tests passed against the corrected host. Eight relevant savekit test programs passed 59 checks covering inventory, user IDs, attributes, storage listing, tree walking, names and manifests.
- The included offline installer test runs 780 legacy IPC packet comparisons, independent mixed-pointer hex/offset checks, NCM validation, and an actual missing-tmp mount inspection with simulated SDK memory. Tampering the manager state causes the expected refusal.
- The integration fixture starts the real host bridge, copies shared and switch2 as the runner does, and launches unmodified upstream save-inventory, save-pull-root --list-uids, pull-inventory and its real pull child as subprocesses. The firmware services, handles, memory and file bytes are simulated. The fixture rejects unexpected service commands. On Linux the retained endpoint stub uses loopback TCP. The same test selects a Windows named pipe on Windows.
- The corrected CLI exercised seven synthetic records. They included a shared multi-chunk archive with a file literally named manifest.json, a nonzero-index secondary cache, a locked UID, a successful common UID, an unreadable file, and a zero-application-ID record with a 64-bit static ID. Five archives verified, including an empty one. The other two remained visible. A denied space yielded unknown coverage. Byte corruption and an extra file in an empty archive failed verification. A stale root failed before the client started. An injected transport error blocked subsequent native calls. Cross-session continuation copied only reverified archives and retained their original capture session. The finish wrapper deferred while a client held the lock and exercised the real parent stop handler with a simulated held session.
- Real Windows 11, a real named pipe on Windows, actual FS permissions and record contents on the test console, throughput, ACNH contents, and restoration were not tested here. The Windows installer reruns its fixture before live use. The author of savekit separately reports a successful Device save with a zero UID and cartridge/removed-title saves on a different console. Neither result establishes ACNH export on the test hardware.
